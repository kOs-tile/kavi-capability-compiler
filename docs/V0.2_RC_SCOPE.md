# v0.2.0 Candidate RC Scope Freeze

Status: candidate scope frozen again after completion of the externally admitted #95 security/correctness fix; external feedback gate remains open.

This document does not publish v0.2.0 and does not declare the final release scope complete. It freezes the current candidate so new work does not enter the release without satisfying the evidence gate in #58.

## Included candidate scope

- deterministic `kcc.delegation-request.v1` and `kcc.delegated-capsule.v1`
- provable parent -> narrower child authority attenuation
- capability / operation / parameter / lifetime / inventory / trust attenuation checks
- clean installed-wheel delegation API execution
- delegated child enforcement through the public inventory-bound Guard
- safe coding-agent integration contract
- deterministic financial classification for explicit exchange/trading order mutations
- credential-free real-consumer exchange execution dogfood
- public deterministic `capability_id(...)` helper for external planners
- dispatch-time host-owned current-authority attenuation for stale valid capsules
- existing dependency-free core and v0.1.1 fail-closed security invariants

## Explicitly excluded from this candidate

- hosted control plane or dashboard
- desktop/local daemon
- generic agent framework
- framework-specific core runtime or required dependencies
- autonomous policy generation or remediation
- signed delegator identity / non-repudiation layer
- Guard API redesign
- broad integration/logo expansion without evidence
- PyPI publication work

## Completed evidence-admitted item

- #95 dispatch-time current-authority / revocation attenuation for stale valid capsules

This item entered the candidate only because external feedback reproduced a real dispatcher-boundary gap. It is now implemented, regression-tested, clean-wheel-tested, merged, and the candidate is frozen again. It does not reopen unrelated feature work.

## Scope reopening rule

The candidate scope may reopen only for evidence that satisfies #58:

- reproducible security/correctness defect
- repeated real integration friction
- measurable over-blocking or authority broadening
- missing generic contract proven by a real consumer
- release/supply-chain correctness defect

Feature requests, framework names, or benchmark headlines alone do not reopen the scope.
